# 04. Настройка сайта и API (мост и генератор 1.1.0)

Сайт — статический, **серверный API не нужен и не вводился**. «Настройка API» сводится к установке моста (`window.postMessage`, протокол v1) в бандл сайта.
Ключей, токенов и переменных окружения мост не использует (`.env.example` описывает только переменные сборки/e2e).

## Что меняется на сайте

Пакет `source/site-integration` ставит **два связанных набора изменений**:

1. **Мост** (`src/extension-bridge/`, 4 файла + тест, 2 строки в `src/main.tsx`) — только вызовы существующих `generateScenario`, `runBatch`, `renderScenario`, `normalizeSettings`. Пассивен: отвечает только на запросы расширения.
   Отдаёт пресеты (встроенные и пользовательские), параметры движка, готовую партию промптов и — только если включена опция «персонаж с сайта» — паспорт внешности сохранённого на сайте персонажа. Cookie, история и прочие данные пользователя не передаются.
2. **Генератор 1.1.0: селфи и реализм** (`src/render/selfie.ts`, `src/render/realism.ts` — новые; `src/render/render.ts`, `src/engine/compose.ts` — заменяются; тест `tests/selfie-realism.test.ts`). Подробно — `07-GENERATOR-CHANGES.md`.
   Схема сценария, выбор сцены, внешности и одежды, правила безопасности и совместимости **не менялись**; изменились тексты промптов и веса ракурса селфи.

Мост зависит от нового модуля `selfie.ts` (параметры селфи попадают в метаданные заданий), поэтому пакет устанавливается целиком.

## Установка в чекаут сайта

```bash
# вариант 1 — скрипт (идемпотентный, с проверкой исходных файлов)
node source/site-integration/apply.mjs /путь/к/promts.vibecods.xyz --check    # что будет сделано / что уже установлено
node source/site-integration/apply.mjs /путь/к/promts.vibecods.xyz            # установить
node source/site-integration/apply.mjs /путь/к/promts.vibecods.xyz --revert   # вернуть исходное состояние
# вариант 2 — патч (должен ложиться на чистый чекаут Juncker38/wefeer@29a55fa)
cd /путь/к/promts.vibecods.xyz && git apply /путь/к/репозиторию/source/site-integration/patches/0001-site-integration.patch

# проверка, что существующий генератор не сломан
npm run typecheck && npm test && npm run build && npm run smoke
```

Скрипт перезаписывает существующие файлы сайта (`render.ts`, `compose.ts`) **только если их хеш совпадает с манифестом** (`manifest.json`, переводы строк CRLF/LF не мешают).
Если файл изменён вручную, установка останавливается (код 3) и ничего не меняет; `--force` перезапишет, сохранив вашу версию в резервной копии (`<сайт>/.rps-site-integration-backup`, скрыта от `git status`).
Windows PowerShell: `npm.cmd` вместо `npm` (как в README сайта).

Результат на чистом клоне `Juncker38/wefeer@29a55fa`: `typecheck` без ошибок, **475 тестов проходят** (417 исходных, 36 тестов моста и 22 теста селфи/реализма), сборка и smoke успешны.

## Проверка моста

В консоли вкладки сайта (при установленном расширении) или кнопкой «Обновить» в панели: статус «Сайт: подключён (движок 1.1.0)».
Без расширения мост ничего не делает. Контракт и коды ошибок — `02-CONTRACT.md`.

## Безопасность моста

* принимаются только сообщения окна страницы с тем же `origin`; формат проверяется строго (`source`, `version`, `id`, тип, диапазоны полей);
* ограничения: до 50 персонажей, до 100 кадров, до 1500 заданий; один запрос создания партии одновременно (`BUSY`); отмена (`cancel`);
* любой скрипт **самой страницы** сайта может вызвать мост (та же доверенная область); чужие origin и iframe игнорируются;
* партия идемпотентна: тот же запрос и seed → тот же `batch_id` и промпты; `created_at` не входит в идентификатор.

## Если понадобится серверный API

Контракт `rps-batch/1` не зависит от транспорта. Минимальный вариант: `POST /api/extension/v1/batches` с `Idempotency-Key = batch_id`, токен с правом «создавать партии», HTTPS, проверка `Origin` расширения, ограничение частоты, журнал без токенов.
Для этого движок пришлось бы запускать на сервере (или собирать партию в браузере и сохранять на сервере). В текущей версии это **не нужно и не реализовано**.

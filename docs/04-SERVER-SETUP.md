# 04. Настройка сайта и API (мост)

Сайт — статический, **серверный API не нужен и не вводился**. «Настройка API» сводится к установке моста (`window.postMessage`, протокол v1) в бандл сайта.
Ключей, токенов и переменных окружения мост не использует (`.env.example` описывает только переменные сборки/e2e).

## Что меняется на сайте

* новый каталог `src/extension-bridge/` (5 файлов: протокол, сборка партии, мост, индекс) — только вызовы существующих `generateScenario`, `runBatch`, `renderScenario`, `normalizeSettings`;
* тест `tests/extension-bridge.test.ts` (35 тестов);
* две строки в `src/main.tsx` (импорт и вызов `installExtensionBridge()`).

Движок, рендерер, настройки и интерфейс **не изменены**. Мост пассивен: отвечает только на запросы расширения.
Что отдаёт мост: пресеты (встроенные и пользовательские), параметры движка, готовую партию промптов и — только если вы включили опцию «персонаж с сайта» — паспорт внешности сохранённого на сайте персонажа. Cookie, история и прочие данные пользователя не передаются.

## Установка в чекаут сайта

```bash
# вариант 1 — скрипт (идемпотентный; --check проверяет, --revert удаляет)
node source/site-integration/apply.mjs /путь/к/promts.vibecods.xyz
# вариант 2 — патч
cd /путь/к/promts.vibecods.xyz && git apply /путь/к/репозиторию/source/site-integration/patches/0001-extension-bridge.patch

# проверка, что существующий генератор не сломан
npm run typecheck && npm test && npm run build && npm run smoke
```

Windows PowerShell: `npm.cmd` вместо `npm` (как в README сайта).

Результат проверки на чистом клоне `Juncker38/wefeer` (HEAD `29a55fa`, `src/` совпадает с сервером): `typecheck` без ошибок, **452 теста проходят** (417 исходных + 35 новых), сборка успешна (JS gzip ≈ 304 КБ против 292 КБ до моста).

## Развёртывание

По `README.md` сайта контейнер `promts-web` (nginx) раздаёт `./dist` через bind-mount: **`npm run build` сразу обновляет продакшен**.
Рекомендуется сначала собрать в отдельном каталоге/на стенде. **Агент продакшен не изменял и не пересобирал** — установка моста на `promts.vibecods.xyz` остаётся за вами.
Политика безопасности `connect-src 'self'` и остальные заголовки не меняются (мост не обращается к сети). Откат: `apply.mjs --revert` или `git checkout -- src/main.tsx && rm -r src/extension-bridge`.

## Проверка моста

В консоли вкладки сайта (при установленном расширении) или кнопкой «Обновить» в панели: статус «Сайт: подключён (движок 1.0.0)».
Без расширения мост ничего не делает. Контракт и коды ошибок — `02-CONTRACT.md`.

## Безопасность моста

* принимаются только сообщения окна страницы с тем же `origin`; формат проверяется строго (`source`, `version`, `id`, тип, диапазоны полей);
* ограничения: до 50 персонажей, до 100 кадров, до 1500 заданий; один запрос создания партии одновременно (`BUSY`); отмена (`cancel`);
* любой скрипт **самой страницы** сайта может вызвать мост (та же доверенная область); чужие origin и iframe игнорируются;
* партия идемпотентна: тот же запрос и seed → тот же `batch_id` и промпты; `created_at` не входит в идентификатор.

## Если понадобится серверный API

Контракт `rps-batch/1` не зависит от транспорта. Минимальный вариант: `POST /api/extension/v1/batches` с `Idempotency-Key = batch_id`, токен с правом «создавать партии», HTTPS, проверка `Origin` расширения, ограничение частоты, журнал без токенов.
Для этого движок пришлось бы запускать на сервере (или собирать партию в браузере и сохранять на сервере). В текущей версии это **не нужно и не реализовано**.
